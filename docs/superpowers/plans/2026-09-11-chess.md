# Chess implementation plan

**Goal:** Deliver playable premium 3D chess in the game collection.
**Architecture:** chess.js adapter → immutable state → React UI and independent Three.js scene. Background worker implements the replaceable AI interface.
**Tech stack:** React, TypeScript, Three.js, chess.js, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-09-11-chess-design.md`

## Constraints

- Preserve existing games and user edits.
- Legal rules live only in `game/engine.ts`; scene code receives legal destinations.
- Optional clocks; local and AI play; original procedural geometry; touch and keyboard input.

## Tasks

- [x] Rules and state: write `game/engine.test.ts` with initial 20 legal moves, pinned pieces, castling restrictions, en passant expiration and exposure, four promotions, Fool's mate, draw conditions, complete undo and elapsed clock checks. Run with `npx vitest run src/games/chess/game/engine.test.ts`, implement types and engine, rerun.
- [x] AI: write `game/ai.test.ts` for legal output, mate in one, material capture, and terminal positions. Implement `chooseMove(fen, difficulty, history)` with bounded alpha-beta search in a Web Worker; verify tests.
- [x] Presentation: procedural board and six distinguishable models, renderer lifecycle, raycasting, motion, flip/zoom, and keyboard controls. React wrapper updates the scene from state only.
- [x] UI and integration: build setup, game panel, promotion/results/settings/help dialogs, persistence, and responsive styles. Register in catalog and provide a chess collection preview.
- [x] Browser validation: local Fool's mate to result, capture and undo, AI reply, keyboard and pointer moves, settings and mobile overflow. Run build, lint, all unit tests, and browser regressions. Inspect screenshots and fix observed issues.
